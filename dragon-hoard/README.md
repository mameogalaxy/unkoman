# ドラゴンホード（Dragon Hoard）

ブラウザで遊べる 3D メダルプッシャー。2003年のアーケード機へのオマージュで、名称・キャラ・絵はすべてオリジナル。

- Vite + TypeScript + three.js
- 物理: `@dimforge/rapier3d-compat`（メダルは本物の円柱剛体、Web Worker で実行）

## 現在の段階: ステージ3（ゲームの流れ）＋改善

- 投入は手前中央の発射台から奥へ撃ち出す方式。画面を左右にドラッグすると照準（緑の枠）が穴を移動し、
  タップで撃つ。穴に入ったメダルはレーンを落ちて上段へ、外れたメダルは壁に当たってフィールドへ落ちる
  （`npm run shoot-test` で各レーンの中央を狙った命中率を確認できる）
- 液晶の中は3Dのダンジョン（`src/screen3d/`）。奥へ続く通路を主人公の後ろから追い、戦闘・宝箱・ボスでは
  カメラが寄る。主人公・スライム・コウモリ騎士・岩の番人・ボスの竜・宝箱は3Dモデル。文字やルーレットは
  2D の canvas を上に重ねて1枚のテクスチャに合成している

- 手持ちメダル（初期100枚）を投入。手前から落ちたメダルが手持ちに戻る。足りなくなったら「メダル補充」
- チェッカー当たり → 保留（最大4）→ 歩数ルーレット（SILVER: 1/3/5/GOLD、GOLD: 3/5/10）
- 4ダンジョン × 3フロア（16マス）→ ボスの間。マスは宝箱（5/10/15枚・宝玉・スロット）と敵（弱・中・強）
- 戦闘: 投入1枚 = 1回攻撃、戦闘中のチェッカー当たりは会心（5ダメージ）。敵は7秒ごとに反撃し、HP が尽きると1マス戻る
- 撃破で敵の強さ別の戦利品ルーレット。ボス撃破でジャックポットスロット、竜が3つ揃うと大ルーレット
- 宝玉8個でも大ルーレット。14マス（500/300/200 が竜マークで連チャン、100×6・50×2 で終了）。回転中はカメラが寄る
- 獲得はすべて「払い出し待ち」に積まれ、竜の口のホッパーからフィールドへ（フィールドが480枚以上なら待つ）
- 手持ち・進行・フィールドのメダル配置を localStorage に5秒ごと保存（`?fresh=1` で保存を無視して開始）
- 進行ロジックは描画から独立（`src/game/`）。`npm run sim -- 120` で2時間ぶんをヘッドレスで回して詰まりと配当内訳を確認できる
- 数値（確率・配当・敵の強さ）は `src/game/rules.ts` に集約。バランス調整はステージ5

## ステージ2（筐体・ライティング・カメラ）

実機写真（液晶が奥壁になった座席視点、画面下の銀のレーン、焦げ茶に金唐草のフード、八角形の筐体と中央塔の大ルーレット・竜の像）を参考に、
構成と雰囲気だけをなぞってキャラ・ロゴ・画面の絵はすべてオリジナルで作っている。

- 奥壁 = 液晶（`src/render/screen.ts`）。上部に主人公・Lv・HP、宝玉ゲージ、予告。下端にレーンのマーク
- 画面下に8本のレーン。メダルは投入口から縦向きに落ち、仕切りの間を通って上段へ。通過レーンはセンサーで検出
- チェッカー: 光るマークが左右に往復し、光っているレーンを通れば当たり（仮で3枚払い出し。ステージ3で歩数ルーレットへ）
- 左奥の城壁の上に竜の頭のホッパー。払い出しは口から勢いよく飛び出す
- 中央の塔に3Dの大ルーレット（14マス、500/300/200 は竜マーク）と竜の像2体、隣のステーション4台
- 暖色の環境マップ、白熱灯、オレンジのランプ管、ブルーム。動かない飾りは材質ごとに結合してドローコールを削減

## ステージ1（物理の検証環境）

```sh
cd dragon-hoard
npm install
npm run dev        # vite --host。同じ Wi-Fi の iPhone から http://<PCのIP>:5173/ を開く
npm run bench      # ヘッドレスで物理コストを計測（node 22 以上）
npm run build      # 型チェック + 本番ビルド（dist/）
python3 scripts/subset-font.py  # 画面の日本語を増やしたらフォントを作り直す（要 fonttools, brotli）
```

### 操作

| 操作 | 内容 |
|---|---|
| 画面を左右にドラッグ | 照準（狙う穴）を動かす |
| タップ / 投入 / スペース | 発射台から1枚撃つ |
| 連射 | 0.3秒ごとに自動投入 |
| メダル補充 | 手持ちに50枚追加 |
| 視点 | 座席 / フィールド / ルーレット / 液晶 / 自由（ドラッグで回転） |
| 光 | ブルームの切り替え（重いとき用） |
| 情報 | 左上の計測表示の切り替え |
| 最初から | 2回押すと保存を消して最初から |

### 検証用 URL パラメータ

| パラメータ | 既定 | 内容 |
|---|---|---|
| `n` | 300 | 初期メダル枚数 |
| `inline=1` | – | Worker を使わずメインスレッドで物理（比較用） |
| `shadow=0` | 影あり | 影を切る |
| `bloom=0` | あり | ブルームを切る |
| `dpr` | 2 | 描画解像度の上限（`dpr=1` で負荷を下げる） |
| `hz` | 60 | 物理の固定ステップ周波数 |
| `cam` | 0 | 初期視点（0 座席 / 1 フィールド / 2 ルーレット / 3 液晶 / 4 自由） |
| `fresh=1` | – | 保存データを読まずに開始 |
| `hud=1` | – | 計測表示を最初から出す |
| `debug=1` | – | `window.dh.game` からゲーム状態を操作できる |

画面左上の HUD に FPS、描画時間、1ステップの物理時間、メダル数、起きている（スリープしていない）メダル数、獲得/ハズレを表示する。

### 設計メモ

- 単位は cm（1 unit = 1 cm）、重力 981 cm/s²、`lengthUnit = 10`。メダルは直径 2.5・厚さ 0.2 の円柱。
- 2段構成: 前後に動くプッシャー台（上段、上面の高さ 3cm、ストローク 8cm・周期 4秒）と固定の下段。
  上段のメダルは奥壁に押されて下段へこぼれ、下段の前端（z=0）から落ちたら獲得、左右の落とし穴はハズレ。
- 固定タイムステップ 60Hz。描画は直前2状態の補間なので 120Hz 画面でも滑らか。物理が間に合わないときは
  1フレーム最大3ステップで打ち切り、スローモーションになる（破綻はしない）。
- 物理は Web Worker で動かし、姿勢だけを Float32Array で受け取る。描画は InstancedMesh 1つ（ドローコール1回）。
- 落ちたメダル（y < -4）は即削除。静止したメダルは Rapier のスリープに任せる。
- 衝突音は接触イベントではなく「重力で説明できない速度変化」から検出（積み重なりの静的な荷重で鳴りっぱなしにならない）。
- メダルの刻印（竜・粒の輪・縁）と側面のギザはコードで生成した高さマップから法線/粗さマップを作る。

### ヘッドレス計測（開発用クラウド VM、Node 22、60Hz、0.4秒ごとに投入）

| 衝突形状 | 350枚 1ステップ平均 |
|---|---|
| 真円柱 `cylinder` | **5.9〜6.3ms** |
| 角丸円柱 `roundCylinder` | 6.2ms |
| 12角柱（凸包） | 7.9ms |
| 20角柱（凸包） | 7.9ms |

ソルバ反復回数（1〜4）ではほぼ変わらず、コストの大半は円柱同士の接触計算。真円柱を採用。
400枚で平均 6.6ms / p95 11ms、すり抜け 0。プッシャーに触れている山は Rapier の島単位スリープの性質上
全体が起きたままになるため、Worker に逃がしてメインスレッドの描画を守る構成にした。
