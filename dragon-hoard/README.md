# ドラゴンホード（Dragon Hoard）

ブラウザで遊べる 3D メダルプッシャー。2003年のアーケード機へのオマージュで、名称・キャラ・絵はすべてオリジナル。

- Vite + TypeScript + three.js
- 物理: `@dimforge/rapier3d-compat`（メダルは本物の円柱剛体、Web Worker で実行）

## 現在の段階: ステージ1（物理の検証環境）

```sh
cd dragon-hoard
npm install
npm run dev        # vite --host。同じ Wi-Fi の iPhone から http://<PCのIP>:5173/ を開く
npm run bench      # ヘッドレスで物理コストを計測（node 22 以上）
npm run build      # 型チェック + 本番ビルド（dist/）
```

### 操作

| 操作 | 内容 |
|---|---|
| フィールドをタップ | タップした左右位置からメダルを1枚投入 |
| 投入 | 直前の位置に1枚投入 |
| 連射 | 0.25秒ごとに自動投入（左右に振る） |
| +30枚 | 30枚をばらまく |
| リセット | 初期配置からやり直し |
| 視点 | プレイヤー / 真上 / 低い位置 / 自由（ドラッグで回転） |

### 検証用 URL パラメータ

| パラメータ | 既定 | 内容 |
|---|---|---|
| `n` | 300 | 初期メダル枚数 |
| `inline=1` | – | Worker を使わずメインスレッドで物理（比較用） |
| `shadow=0` | 影あり | 影を切る |
| `dpr` | 2 | 描画解像度の上限（`dpr=1` で負荷を下げる） |
| `hz` | 60 | 物理の固定ステップ周波数 |
| `cam` | 0 | 初期視点（0〜3） |

画面左上の HUD に FPS、描画時間、1ステップの物理時間、メダル数、起きている（スリープしていない）メダル数、獲得/ハズレを表示する。

### 設計メモ

- 単位は cm（1 unit = 1 cm）、重力 981 cm/s²、`lengthUnit = 10`。メダルは直径 2.5・厚さ 0.2 の円柱。
- 2段構成: 前後に動くプッシャー台（上段、上面の高さ 3cm、ストローク 8cm・周期 4秒）と固定の下段。
  上段のメダルは奥壁に押されて下段へこぼれ、下段の前端（z=0）から落ちたら獲得、左右の落とし穴はハズレ。
- 固定タイムステップ 60Hz。描画は直前2状態の補間なので 120Hz 画面でも滑らか。物理が間に合わないときは
  1フレーム最大3ステップで打ち切り、スローモーションになる（破綻はしない）。
- 物理は Web Worker で動かし、姿勢だけを Float32Array で受け取る。描画は InstancedMesh 1つ（ドローコール1回）。
- 落ちたメダル（y < -4）は即削除。静止したメダルは Rapier のスリープに任せる。
- 衝突音は接触イベントではなく「重力で説明できない速度変化」から検出（積み重なりの静的な荷重で鳴りっぱなしにならない）。
- メダルの刻印（竜・粒の輪・縁）と側面のギザはコードで生成した高さマップから法線/粗さマップを作る。

### ヘッドレス計測（開発用クラウド VM、Node 22、60Hz、0.4秒ごとに投入）

| 衝突形状 | 350枚 1ステップ平均 |
|---|---|
| 真円柱 `cylinder` | **5.9〜6.3ms** |
| 角丸円柱 `roundCylinder` | 6.2ms |
| 12角柱（凸包） | 7.9ms |
| 20角柱（凸包） | 7.9ms |

ソルバ反復回数（1〜4）ではほぼ変わらず、コストの大半は円柱同士の接触計算。真円柱を採用。
400枚で平均 6.6ms / p95 11ms、すり抜け 0。プッシャーに触れている山は Rapier の島単位スリープの性質上
全体が起きたままになるため、Worker に逃がしてメインスレッドの描画を守る構成にした。
